# A5 final E2 certification and E3 capacity-gate report

## Decision

`NO_GO_A5_E2_OR_QUEUE_INVALID`

This is a pre-outcome infrastructure and protocol-size No-Go. It is not a

## Final E2 numerical certification

The frozen H4 singleton and K=2 joint paths were repeated using the final A3
grammar and four-layer identities. Both mapped-warm and zero-coordinate starts
were executed for each target. All four endpoints passed the independent
energy, state, analytic-gradient, constraint, and resource certificates. A
second complete CPU execution was scientifically identical after timing fields
were removed.

The optimizer family, analytic-gradient semantics, tolerances, two-start
policy, seeds, thread policy, and per-start limits were frozen only from E2.
The previously frozen A1 transaction audit remains the engineering evidence
for injected optimizer/artifact failures, exact rollback, and same-request
retry. A5 did not reinterpret either H4 probe as Phase-1 molecular performance.

## Why E3 was not frozen

The complete registered A3 language contains 88,148 molecular targets:

| Case | Complete targets | Requested optimizer starts |
|---|---:|---:|
| LiH 3.0 A | 75 | 150 |
| H6 1.5 A | 40,946 | 81,892 |
| H6 3.0 A | 46,101 | 92,202 |
| BeH2 3.0 A | 1,026 | 2,052 |
| **Total** | **88,148** | **176,296** |

The E2-derived per-start limits imply an upper bound of 17,629,600 optimizer
iterations. Merely beginning one analytic gradient for every registered start
would expose 24,566,848 target-coordinate gradient components. At A5 there is
no demonstrated request-bound runner/checkpoint/ledger capacity or frozen
total-study primitive-work cap covering this complete workload.

The protocol forbids silently replacing exhaustive enumeration with Top-K,
random sampling, removal of expensive cases, or outcome-informed ranking.
Therefore no E3 queue was created and no molecular candidate energy,
optimizer start, or FCI evaluation occurred.

## Consequence for the current plan

A6 frozen E3 execution, A7 frontier reconstruction, and A8 terminal scientific
analysis are not authorized. The current Phase-1 v1 execution terminates at
A5 with a formal No-Go.

A protocol successor may proceed only by either:

1. defining a substantially smaller prospective joint language using only
   outcome-free CEO algebra, symmetry, or exact resource-equivalence rules; or
2. demonstrating and freezing infrastructure and a total-work cap that admit
   exhaustive execution of all 88,148 targets.

No existing E3 result can influence that choice because no E3 outcome exists.

## Verification status

The Phase-1 test partition completed with 24 passed tests under the registered
A2 single-thread environment. An earlier invocation with two BLAS/OpenMP
threads produced one expected thread-policy rejection; rerunning with the
frozen environment passed and did not require a code change.

An all-repository regression invocation reached approximately 28 percent
without a test failure before it was terminated with SIGTERM after about 17
minutes. A second invocation excluding the direct public-scan test reached the
same history scanner indirectly through an S0 manifest audit and was also
terminated. The delay came from the pre-existing scanner running several
full-tree `git grep` operations separately over each of 422 historical commits.
Neither invocation produced a scientific outcome or artifact, and neither is
represented as a green full-suite run.
