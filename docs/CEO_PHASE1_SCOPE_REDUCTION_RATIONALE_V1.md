# CEO Post-Growth Compression Phase 1: Scope-Reduction Rationale v1

Status: planning document; no outcome-bearing run is authorized by this file.

## 1. Why this reduction is necessary

The project has accumulated several scientifically useful ideas and an unusually strong audit framework. It has also accumulated too many simultaneous questions. The immediate risk is no longer a lack of safeguards; it is that the central scientific estimand becomes obscured by infrastructure, optional mechanisms, and post-hoc analyses.

Phase 1 therefore asks one narrow question:

> For a fixed, fully reoptimized CEO* source ansatz, does a bounded joint structural transformation attain a lower **observed accuracy-feasible canonical CNOT count** than both the complete registered singleton transformation universe and the fully reoptimized CEO* prefix oracle?

Everything retained must be necessary to answer that question fairly. Everything else is deferred or removed from the Phase 1 critical path.

## 2. What the historical evidence actually supports

The following observations motivate a prospective test, but they are not confirmatory evidence.

| Historical observation | Correct interpretation | What it does not prove |
|---|---|---|
| LiH 3.0 Å development result: canonical CNOT 107 to 58, parameters 15 to 8, with a reported energy increase of about 8.69e-5 Ha | Large post-growth compression can exist in at least one historically selected case | Generalization, matched-work superiority, or prospective success rate |
| V4.1 development results included about 45.8% CNOT reduction for LiH and about 15.9% for BeH2 | The signal is not restricted to a single molecule in the exploratory record | Independence of samples or a population-average effect |
| H6 development reductions were much smaller, around a few percent in several cases | Compression value is heterogeneous and may depend on source structure | A universal CEO-specific mechanism |
| Later matched-work records showed modest average CNOT improvement among valid completed pairs, and several methods were rejected or operationally fragile | A large historical best-found result must not be treated as the typical prospective result | That compression has no value; the study was designed for different endpoints and methods |
| V6/native-synthesis investigations often produced only small gains or negative cases | Broader rewrite and synthesis families are not automatically valuable | That the narrower joint-versus-singleton estimand is already answered |

These results justify **testing whether a real structural interaction exists**. They do not justify beginning with a complex predictor, a lifecycle theory, or a publication-level molecular campaign.

## 3. Items retained in Phase 1

### 3.1 Canonical B2 source and full-ansatz reoptimization

Retained because the target is post-growth compression of an already optimized CEO* ansatz. Source eligibility, parameter stationarity, and immutable source identity are necessary to prevent a poor or mismatched source from creating artificial compression.

### 3.2 Parameter-to-circuit materialization and full resource recount

Retained because deleting a small parameter does not necessarily delete a CEO block, CNOT skeleton, or circuit layer. The experiment must compare materialized circuits, not parameter vectors.

### 3.3 Complete registered singleton universe

Retained because the primary scientific claim is about nonseparability. A truncated or ranked singleton list would allow a joint method to appear superior merely because the correct singleton was never evaluated.

### 3.4 Bounded joint universe

Retained with `K=2`, structural-dependency locality `L=1`, and source rewrite depth `D=1`. Pairwise interaction is the smallest experiment that can establish non-additivity, while higher cardinalities expand combinatorially and are not needed for the first decision. The result is explicitly about this registered bounded language, not all possible circuit rewrites.

### 3.5 Optimization parity and two registered starts

Retained because nonconvex optimization can make a topology look bad or good for initialization-dependent reasons. Each target topology receives the same optimizer contract and the same two start classes. The output is an observed frontier, not a proof of the global optimum.

### 3.6 Fully reoptimized CEO* prefix oracle

Retained because a compressed final circuit is not valuable if an earlier CEO* prefix already attained equal accuracy at equal or lower CNOT count under the same optimization contract. This is a retrospective oracle comparator, not an online stopping rule.

### 3.7 FCI firewall

Retained because FCI may define reporting error but must not select candidates, tune thresholds, rank methods, or terminate searches. The primary acceptance loss is relative to the frozen B2 source.

### 3.8 Evidence classes and immutable identities

Retained in a reduced form because historical exploration, development, prospective confirmation, and untouched validation must not be mixed. Four separate identities prevent structure, candidate plan, initialization, and optimized endpoint from being conflated.

### 3.9 Raw work counters and transactional results

Retained because comparisons require interpretable computational work and safe restart. The counter set is intentionally small and bound to actual kernel events; failed and rejected attempts remain visible.

### 3.10 Production vertical slice before queue freeze

Retained because earlier work repeatedly built queues, adapters, caps, and releases before proving that one real molecular request could traverse the complete kernel path. H2/H4 vertical slices now precede the confirmatory queue.

## 4. Items deferred to Phase 2

| Deferred item | Why it is not required for Phase 1 | Condition for restoration |
|---|---|---|
| Joint cardinality `K>2` or sequential depth `D>1` | Pairwise `D=1` is the minimum nonseparability test; larger searches mix interaction order with search policy | A pairwise signal is replicated or a separately registered higher-order hypothesis is justified |
| Hessian/OBS ranking and CEO-aware B5 | Enumeration, not ranking, is the Phase 1 test. Ranking would introduce another hypothesis and fairness problem | Joint value is observed and enumeration exceeds a registered practical cap |
| Generic second-order additive baseline B3e | Needed only if a Hessian-informed CEO-aware method is developed | Automatically required when B5 uses Hessian information |
| Lifecycle, scaffold, QGT, and causal diagnostics | Interesting mechanisms, but retrospective stories cannot establish the primary effect | A replicated joint advantage survives prefix comparison |
| Survivor-only replay and direct-topology retraining | Strong mechanistic controls, but they do not answer the first existence question | Phase 1 shows a robust effect worth explaining |
| TETRIS/topology-aware growth | Changes source construction and therefore changes the estimand | Separate future study after post-growth value is established |
| Co-ADAPT or other source families | Useful for external validity, but source heterogeneity would slow the first decision | Phase 2 validation branch with a frozen cross-source question |
| Measurement Cost reconstruction | Requires a separate estimator/grouping/reuse contract and is not identical to energy evaluations | Circuit benefit exists and a concrete repeated-measurement use case is registered |
| Noise and hardware execution | State-dependent equivalence and compiler effects need separate guarantees | Noiseless structural result survives and a hardware claim is planned |
| Multi-compiler/routing robustness | Important for hardware relevance but not for the canonical logical estimand | Phase 2 structural validation |
| Break-even analysis | Meaningless without a registered reuse workflow | A measurement/property-estimation workflow is specified |
| A100 acceleration | Engineering optimization, not scientific evidence | CPU/GPU parity is proven and CPU execution is a demonstrated bottleneck |

Deferred means **not discarded**. It means the item cannot delay or alter the Phase 1 decision.

## 5. Items removed from the core research claim

### 5.1 A combined “best V5” algorithm

Removed because OGM, measurement reuse, pruning, sequential rebuild, beam search, Hessian ranking, and synthesis changes answer different questions and change different cost definitions. Combining them would make attribution impossible.

### 5.2 Five-objective Pareto dominance as the primary conclusion

Removed because dominance becomes rare as dimensions are added and can make nearly all methods incomparable. The primary endpoint is now constrained and interpretable: minimize canonical CNOT count subject to a frozen energy-loss constraint. Other resources remain secondary outcomes.

### 5.3 Per-microstep release, tag, and human-approval gates

Removed from the critical path because they created administrative latency without changing the scientific estimand. Code review, immutable terminal artifacts, CI, and owner protocol freeze remain. Human scientific advice may be recorded, but it is not a blocking software primitive.

### 5.4 Generalized proxy adapters and a six-method framework

Removed because abstract planning controllers repeatedly passed tests without proving method-native molecular semantics. Phase 1 implements only the actual source, singleton, joint, and prefix paths required by the question.

### 5.5 Rank lattices, native synthesis, and unbounded rewrite search

Removed because earlier investigations showed that lower algebraic rank does not guarantee lower CNOT count and broader synthesis did not reliably create large gains. Exact registered reductions may be included only when they are part of the frozen Phase 1 language.

### 5.6 “Temporary scaffold” as the central claim

Removed because fading and optimization-path effects are already natural in ADAPT-type methods, removable blocks are post-selected, and the effect may not be CEO-specific. Phase 1 tests a directly measurable frontier gap. Mechanism is conditional Phase 2 work.

## 6. Why this is faster without becoming weaker

The reduction removes work that cannot change the first decision. Phase 1 does not need to prove why a joint advantage occurs, predict it online, reconstruct measurement cost, or validate hardware robustness before determining whether the advantage exists prospectively.

The critical path is therefore:

1. isolate the scientific parent and freeze the source contract;
2. run one production H2/H4 vertical slice;
3. enumerate the complete singleton and bounded joint languages on CPU;
4. freeze the prospective queue and optimizer contract;
5. execute only the minimum molecular panel needed for the Phase 1 decision;
6. stop, replicate narrowly, or authorize one Phase 2 branch.

This is scientifically stronger than a larger experiment because every computation maps to one prespecified estimand.

## 7. Change-control rule

Before Phase 1 terminal analysis, a new suggestion may enter the critical path only if it fixes one of the following:

- incorrect source identity;
- incorrect transformation semantics;
- optimization unfairness;
- outcome leakage;
- invalid resource accounting;
- unrecoverable execution behavior.

Suggestions that only add interpretation, breadth, prediction, acceleration, or publication polish go to the Phase 2 backlog. This prevents external feedback from turning the protocol into another patchwork plan.
